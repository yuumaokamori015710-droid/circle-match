# サークルの公開連絡先調査

自動調査の結果は管理者専用 `/admin/contact-research` に保存する。自動判定だけで公開プロフィール・公開APIへ追加しない。公開情報の取得は、送信、配信同意、本人確認を意味しない。

2026-10-14: 利用者の全団体調査の依頼を受け、9,350団体を全件再走査。既存キャッシュを読み取り専用で再利用し、追加434ページを確認した。旧候補と新候補を合わせた340団体の掲載元を開き直し、団体名・用途を確認した連絡先を `outputs/circle_public_contacts.json` へ追加した。公開窓口は8件から319件（大学253件・社会人66件）へ増加。未取得は9,031件であり、全件取得済みではない。ログイン用・代表申請用アドレスや自動調査結果全体は公開しない。

起動時に `circle_public_contacts` テーブルへ団体ID・名前・登録出典URLの一致を確認して取り込む。登録出典から公式サイトへ移動した場合は `circle_source_url` が元の団体の照合用URL、`source_url` が実際のメール掲載URLとなる。取得日の新しい確認結果のみ更新する。プロフィールの非公開指定や `enabled=0` は優先し、再取り込みで解除しない。元データや利用者のプロフィール・申請情報を書き換えない。

公開検索APIはこの個別確認済み窓口も返す。招待作成画面ではメール、公開用途、出典、確認日を表示する。招待作成後の送信者画面に `mailto` ボタンがあり、宛先・件名・本文・招待リンクをメールアプリへ渡す。リンク作成だけでは送信せず、「送信済み」とも表示しない。メール未確認時は掲載元へのリンクを表示する。公認・代表権限・招待受信同意を付与しない。

`scripts/research_circle_contacts.py --directory <private-directory>` は現在の公開サークル一覧を全件スナップショットし、登録出典と団体名で対応するリンクを確認する。同じURLはキャッシュし、robots.txt、ホスト別のアクセス間隔、HTTP失敗を記録する。ログイン必須のSNS、非公開サイト、別団体のプロフィール、大学・掲載サイトの共通窓口は自動採用しない。メールは団体名を含む限定的な文脈で確認し、同じメールが複数団体に出現した場合は要確認へ戻す。

出力ディレクトリはGit管理外に置く。`results.jsonl` は再開用、`pages.sqlite` は取得キャッシュ、`results.json` は管理者専用取り込み用、`contacts.csv` は全件の状態・公開根拠、`progress.json` は集計を保持する。CSVの各メールには大学名・団体名・出典・確認日時を対応させる。協賛専用などの用途は根拠欄で確認する。実行中のPCを終了すると処理は止まるが、同じコマンドで保存済みから再開できる。

複数団体を載せるページでは、同じ表の行や見出しの節にある連絡先だけを対応させる。別団体の見出しを越えて連絡先を採用しない。専用ページの見出し、階層、共通窓口の表示も確認し、取得済みキャッシュで再評価する。ページ内で形式が似ていても、SNSのプロフィールURLや質問者の投稿欄は団体メールとして扱わない。

状態はメール確認、確認範囲で未発見、問い合わせ先候補、取得できず、参照先なし、要確認に分ける。「未発見」はウェブ全体や非公開情報にも存在しないという意味ではない。出典が古い、画像だけに記載されている、別名称で運営されている場合などは追加調査を要する。アドレスの推測や非公開窓口への侵入は行わない。

`--reuse-cache <previous-pages.sqlite>`（複数指定可）で前回のキャッシュを変更せず利用できる。キャッシュ内の失敗も再利用するため、失敗URLの再試行には新しい調査ディレクトリで当該キャッシュを渡さない。`source_checked_at` はページの実際の取得日時であり、再解析しただけでは現在日に更新しない。

`scripts/review_circle_contact_candidates.py --inventory <circles.json> --research <results.json> --directory <private-review-directory>` は候補の掲載元を再取得する。既定では以前の取得キャッシュを使わず、同じ団体の公開窓口として再確認できた候補と却下理由を出す。共有メールは自動採用しない。この処理だけでは公開JSON・DBを更新しない。今回も15件の入試・寄附・車両利用・OB会専用窓口、教授紹介のみのメール、返信受付なしのアドレスを追加レビューで除外した。協賛・取材窓口や顧問窓口には用途を明記した。

取り込み例：

```
python scripts/import_contact_research.py --file <private-directory>/results.json --validate-only
python scripts/import_contact_research.py --file <private-directory>/results.json --credentials-file <temporary-admin-connection.json>
```

認証情報は既存Render環境の管理者資格情報を使い、一時ファイルは取り込み後に削除する。新しい資格情報や権限は作成しない。250件ずつ原子的に取り込み、再試行しても重複しない。管理画面・JSON・CSVには既存の管理者認証が必要で、認証設定がなければ503で拒否する。管理者用の自動調査取り込みと、上記の個別確認済み公開窓口は別に扱う。

管理者の調査一覧・集計・CSVは公開サークルDBと同じ掲載対象に絞る。デモや掲載審査中の団体は対象件数へ含めない。掲載から外れた団体の過去の調査履歴は削除しない。
