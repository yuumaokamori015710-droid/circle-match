# 最初の主催者と募集を集める

## 今回のゴール

新機能を増やすより、実在する主催者3〜5組が、実際の募集を5〜10件掲載し、
参加申込から開催連絡まで使える状態を作る。数字は目標であり、現在の実績ではない。
テスト募集を本番に公開したり、外部サイトの募集を無断転載したりしない。

## 最初の2週間

1. 関東の、今後1〜2か月以内に開催予定がある主催者を10組まで候補にする。
   最初は運営者の知り合い・紹介を優先。競技は協力してもらえる主催者がいるものを選ぶ。
2. 最初の3組に個別に説明し、各1件の実在イベントを掲載してもらう。
   既存DBへの掲載は、代表権限や勧誘への同意を意味しない。
3. 主催者本人のアカウントで入力・プレビュー・公開する。運営は入力を支援しても、
   主催者になりすましたり、パスワード・ログインリンクを受け取ったりしない。
4. 主催者の既存SNS・グループに募集詳細URLを共有してもらう。
   初期の集客は既存コミュニティとの併用とし、Circle Matchだけで人が集まるとは約束しない。
5. 各募集の最初の申込を主催者と確認する。先着は参加確定、承認制は承認待ちを区別する。
6. 1週間後に入力で困った箇所、問い合わせ、キャンセル理由を聞く。
   再開催を予定する主催者には「複製」で次回の募集を作ってもらう。

## 主催者に事前に揃えてもらう情報

- 名称、競技、募集種別、開催日時、会場・都道府県、当日の内容。
- 個人／チーム、定員と単位、参加条件、先着順／承認制、応募締切。
- 参加費と単位、無料／現地払い／口座振込。振込先は参加確定後に個別案内する。
- 主催者の表示名・連絡先、キャンセル期限、荒天・人数不足時の中止条件。
- 団体紹介へのリンクが必要な場合のみ、代表権限の確認。DB掲載だけでは紐付けない。

## 公開前チェック

- 主催者本人が開催内容を確認し、掲載に同意している。
- 過去の開催日や、確保していない会場を記載していない。
- 「2チーム」と「20人」、「1チーム2,000円」と「1人2,000円」を取り違えていない。
- 誰が参加できるか、承認が必要か、キャンセル・中止時の扱いが読める。
- 口座情報・参加者の個人情報を公開説明に入れていない。
- 主催者がマイページで申込と通知を確認できる。

## 連絡と運用上の注意

候補・連絡履歴は非公開の表で管理する。項目は「主催者名、公式情報のURL、競技・地域、
連絡経路、本人の同意、連絡日、回答、公開URL、申込件数、継続意向」。
連絡先の推測や大量送信はしない。営業・掲載案内を受け付ける窓口かも確認する。
Resendの通知基盤は認証・イベント取引通知用であり、勧誘の一斉送信に転用しない。
notifications@circle-match.jp は送信専用。返信先として案内しない。
受信できる運営者の連絡先を確認してから依頼文を送る。

週に一度、公開された実募集数、申込数、承認の滞留、メール送信失敗、
再掲載したい主催者数を確認する。DB収録件数を利用者数や成約実績として宣伝しない。

## 次に運営者が決めること

最初に声をかける主催者を3組選ぶ。名前・連絡経路・実際の開催予定を確認する。
宛先と依頼文の承認後に個別案内へ進む。現時点では案内の送信も、実募集の代理掲載も行っていない。
